## 1. 版本与插件兼容性

新增独立的 Sub2API 宿主版本比较规则：

```text
v0.2.19 < v0.2.19p1 < v0.2.19p2 < v0.2.19p10 < v0.2.20
```

- `pN` 是后续修订号，不作为 SemVer 预发布版处理；按数值顺序比较，避免字符串排序和整数溢出。
- 更新检查的实时、缓存及回滚版本筛选使用同一规则。无效版本不再被默认为零。
- 插件 `requires.sub2api` 使用宿主规则；`=0.2.19` 不匹配 `0.2.19p1`。
- 仅声明测试过 `0.2.19` 的插件，在范围允许的 `0.2.19p1` 上仍标记为 `untested`，保留显式接受未测试版本的机制。
- 插件启动、周期性恢复、启用以及运行时准备前重新检查兼容性。不兼容时当前实例的插件路由报不可用，不静默回退直连，也不因此修改其他实例共享的已启用绑定。
- 插件包自身版本、协议版本、Transport API、UI Bridge 的规则不变；Codex/Claude 客户端版本比较不变。
- 发布辅助脚本的版本校验支持 `pN`，添加纯本地计划测试；不代表已进行实际发布验证。
- 更新源仍为 `Wei-Shaw/sub2api`，没有改成 fork。比较规则支持 `pN` 不等于自动发现 fork 自己发布的修订版。
- 未修改当前 `VERSION` 文件或 Codex 默认身份；构建版本仍由既有构建信息提供。

## 2. 请求入口观测

### 配置与 UI

管理员「系统设置 → 安全 → 请求入口记录」（位于 API Key IP 访问控制之后）：

| 配置 | 数据库存储键 | 默认值 |
|---|---|---|
| 校验入口转发头的代理来源 | `request_ingress_validate_proxy` | `false` |
| 入口可信代理 IP / CIDR | `request_ingress_trusted_proxies` | `[]` |

配置存于现有 `settings` 表，经管理员设置 API 保存，无需配置 YAML 或重启。支持最多 256 个 IPv4、IPv6、CIDR；UI 支持换行、空格和逗号分隔。服务端验证、规范化、去重；无效输入整次保存失败。关闭校验时也可预先保存列表。

保存后本实例立即更新；其他实例按 60 秒缓存周期、下一次请求触发后台刷新。刷新失败保留已有策略并在 5 秒后重试；启动时无法读取策略则暂时仅使用 Host，避免在配置未知时扩大信任。

### 逻辑变化

| 场景 | 记录的入口 |
|---|---|
| 默认关闭校验，合法单值 `X-Forwarded-Host` | 该头的 host/IP，可含端口 |
| 没有该头，或为 URL、多个值、非法内容 | `Request.Host` |
| 开启校验，直接 TCP 对端命中可信列表 | 合法 `X-Forwarded-Host` 优先，否则 Host |
| 开启校验，对端不命中或列表为空 | 忽略转发头，仅使用 Host |

可信来源仅取 `RemoteAddr` 的直接对端，不使用客户端 IP 兼容解析、不用 X-Forwarded-For 来证明代理可信。IPv4-mapped IPv6 会统一匹配 IPv4。字段长度受限，不记录 URL 路径、查询参数、用户信息或完整请求头。

记录格式：

```json
{"request_ingress":{"host":"api.example.com:8443","source":"forwarded_host","peer_ip":"10.20.0.5"}}
```

管理员 Usage 列设置可打开默认隐藏的「入口」列；错误请求列表也可打开，错误详情和 HTTP access log 同样包含入口。2026-11-05 将展示标签从 `Direct peer` /「直接对端」缩短为 `Peer` /「对端」，不改变字段及取值。普通用户的 Usage/错误 DTO 不增加内部入口信息。既有历史行没有入口，显示 `—`，不作推测性补填。

HTTP、SSE 以及原生 WS 从入站请求取得不可变快照，异步记录和计费写入兜底保留它。WS 各轮沿用该连接握手时的入站入口，而非上游池连接的地址。已建立的 WS 连接不会因管理员更改配置而重写此前捕获的入口。

cyber 错误的独立后台补记及本地阻断日志也携带入口快照。没有原始入站上下文的独立后台任务（例如批量图片任务后台结算）不推断入口，保持空值；本轮未扩展这些任务自身的持久化协议。

### 你目前的部署如何使用

保持默认关闭校验即可，不必改动现有客户端 IP 配置。入口会优先取 `X-Forwarded-Host`，否则取 Host；多 Caddy、Nginx、IP 直连使用同一逻辑。

若以后开启校验，在列表填写 **sub2api 实际看到的直接对端**。可先从入口列的「对端 / Peer」核对：经 Docker/NAT 后，它可能是内网地址，不一定是反代公网 IP。此列表不会替代 `server.trusted_proxies`，也不控制原客户端 IP 解析。

反代应覆盖而非追加来自客户端的 `X-Forwarded-Host`。Nginx 若只发送默认的上游 Host，记录会是上游地址，需要自行保留外部 Host 或设置 `X-Forwarded-Host`。本轮不自动修改任何反代配置。

**默认不校验意味着直连客户端可以伪造入口声明。** 这是按本轮要求保留的观测信任模式，不能把入口字段用于鉴权、计费、路由或安全归因。即使开启校验，可信反代也必须正确覆盖头。

无法仅凭域名可靠还原反代公网 IP；不做 DNS 查询，也不猜测 NAT 前地址。

### 开销与迁移

- 请求热路径读取内存中的已编译策略；不逐请求查数据库、Redis 或 DNS。
- 默认模式为有限长度的 host 解析；严格模式最多匹配 256 个 IP 前缀。不会扫描全量账号、Key 或日志。
- 入口 JSON 随已有 usage/error INSERT 一起写入，不增加独立写入请求。错误日志队列字节预算包含新增字段。
- 新迁移 `249_request_ingress_observation.sql` 仅在 `usage_logs`、`ops_error_logs` 增加可空 JSONB 列，无默认值、无历史回填、无新索引。运行时仍须按正常流程应用迁移；ALTER TABLE 的短时锁需遵循现有发布安排。
