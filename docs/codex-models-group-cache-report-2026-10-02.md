# 分组 Codex OAuth 上游目录缓存配置

位置：分组管理 → 编辑 OpenAI 分组 →「固定账号获取模型列表」下方的「Codex OAuth 上游目录缓存」。两个输入框始终显示，不要求开启固定账号选择。

| 配置 | 默认值 | JSON 字段（位于 codex_models_manifest_config 内） |
| --- | --- | --- |
| 新鲜缓存时长 | 60 秒 | `oauth_cache_ttl_seconds` |
| 缓存最大可用年龄 | 300 秒 | `oauth_cache_stale_ttl_seconds` |

两项均从最近一次成功拉取（包括上游 304 验证成功）时刻起算，**不是累加**。

- 缓存年龄小于新鲜时长：直接返回缓存，不请求上游。
- 达到新鲜时长但小于最大年龄：返回旧值，并在后台 singleflight 刷新。
- 达到最大年龄：同步等待上游拉取；失败时返回错误，不继续返回超龄目录。
- 两个值相等：没有后台刷新区间。两项均为 0：不保留目录结果缓存，仍合并同时在途的相同请求。
- 接受整数秒，范围 `0 ≤ 新鲜时长 ≤ 最大年龄 ≤ 86400`，前后端均校验。

## 范围与兼容

- 只作用于分组实际从 Codex OAuth 上游获取的目录。固定账号、固定账号失败后的调度回退、普通 Codex 调度发现使用同一分组策略。
- 固定账号普通 `/v1/models` 列表若使用 OAuth 数据源，也应用该策略并与同策略的 Codex manifest 复用源缓存。
- API Key 上游仍采用原有 60/300 秒策略；没有分组上下文的管理员账号探测也使用默认值。
- 不改变本地目录内容、模型元数据、映射/合并/白名单规则，也不改变客户端自己的目录缓存或 ETag 协议。纯本地目录响应不因此产生上游查询。
- 使用现有分组 JSON 配置列，无需数据库迁移。旧分组没有字段时沿用 60/300；修改分组时省略新增字段会保留已有值，避免旧管理客户端覆盖配置。
- 两个配置字段进入管理员 DTO、数据库账号认证投影及认证缓存快照。分组更新沿用已有认证缓存失效机制。
- 复制分组时复制缓存时间，但依旧关闭固定账号模式并清空其账号列表；缓存时间使用独立副本。

## 隔离与开销

- 缓存键和 singleflight 键包含最终生效的新鲜/最大年龄。不同策略不能串用缓存期限或后台刷新；同账号、同请求身份、同策略仍可共享源目录，分组过滤继续在缓存之后执行。
- 保存新时间后，后续拿到新分组配置的请求使用新策略键，不等待旧条目原定过期。没有进行全局缓存清空。
- 没有增加定时轮询器，仅在已有目录请求触发时刷新。TTL 越短，上游请求可能越多；设为 0 是显式关闭对应缓存区间。
- 仍是单个进程级缓存：最多 512 项，每项 `Body + upstreamSourceBody` 合计不超过 1 MiB；没有为每个分组新建 512 项。不同策略组合可能增加条目数并加快淘汰，旧策略条目仍按既有淘汰逻辑清理。
- 以上是缓存正文的逻辑容量限制，不是整个进程的堆内存硬上限；切片容量、请求副本、结构体及在途拉取仍有额外开销。
