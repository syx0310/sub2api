### credits 状态与账号归属

- 手动查询结果缺失 credits 表示未知，不制造零余额，也不凭空生成耗尽锁定。余额仍保留上游字符串表示。
- 查询母账号时，展示快照与策略状态在同一次 Extra 更新中保存；查询影子账号时，展示快照仍写被查询行，策略证据和耗尽锁定写凭据所属母账号。不会授予影子账号独立的消费许可，也不修改母账号套餐窗口。
- 被动写入可能早于手动刷新开始、晚于它完成。因此 `UpdateExtra` 对 `BlockedAt` 使用数据库当前值与传入值的最大值，防止迟到的旧被动写入抹掉锁定。重新授权仍通过推进 `resume_at` 表达，不删除锁定历史。
- 自然套餐额度恢复仍允许套餐内请求；本次没有改变“仅在已知套餐耗尽时检查 credits”的范围。
- 没有增加上游余额轮询、充值、重置卡消费、充值后探测或自动恢复逻辑。手动刷新沿用已有的显式查询结果。

### steer 语义边界

OpenAI Docs 核对影响了本次实现：accepted 输入已经由上游持有，后继可以消费多条已接受输入，因此聚合只用于本地审计，不能构造额外 `response.create` 重新发送。自动后继继续继承原请求设置，单条 steer 的审计输入形状保持兼容。依据：[Responses steering 事件定义](https://developers.openai.com/api/reference/cli/resources/beta/subresources/responses)、[Mid-turn steering](https://developers.openai.com/api/docs/guides/steering)。

本次不扩展 ctx_pool steering、多 lane 或显式工具续链功能。其他父响应的 accepted 队列保持不变。消费和删除队列时清理底层切片中的 payload 引用，避免长连接继续持有已经处理完的输入。

## 性能影响

- 普通母账号的候选过滤不新增数据库/上游查询，只在既有摘要中增加四个必要字段及其解析成本；完整账号读取仍发生在通过候选过滤之后。账号更新刷新摘要不要求重建 bucket 成员。
- HTTP → 上游 WS 增加发送前策略检查，复用已有调度快照；每次快照读取仍受既有 100ms 截止时间约束。开启可选预热时，在预热完成后还会检查一次。
- 手动余额刷新增加一次账号读取；影子账号额外读取母账号，并增加一次母账号策略写入。仅由管理员显式刷新触发，不增加 OpenAI 查询次数。
- `BlockedAt` 保护在原 SQL UPDATE 内完成，不增加锁定查询或新数据库迁移。被动观测仍使用原有 30 秒节流、关键变化快速持久化和最多四个写入者。
- 多 steer 聚合成本与本次被消费的输入总大小成正比；不复制整段对话历史，原始帧不再次发往上游。
